# AI CAD project watch - 2026-06-01

## 扫描范围

本次检查 AI + CAD / CAD MCP / agentic hardware design 方向的新项目和老项目更新，重点关注：

- CAD agent / text-to-CAD / prompt-to-CAD
- build123d / CadQuery / FreeCAD / Onshape / KiCad / ZWCAD MCP
- AgentCAD、CAD skill、STEP 生成、渲染、验证、工程图自动化
- 与硬件结构设计、机箱、散热器、液冷机柜长期路线相关的工具链

## 重点发现

### 1. build123d-mcp

- 仓库：[pzfreo/build123d-mcp](https://github.com/pzfreo/build123d-mcp)
- 状态：2026-06-01 仍在高频更新。
- 定位：把 build123d CAD 操作封装为 MCP 工具，让 agent 可以执行代码、注册零件、渲染视图、查询尺寸、迭代修改。
- 判断：高度契合当前路线。它比完整 CAD 软件自动化更窄，但对参数化零件、机箱结构基准、散热器、小夹具这类任务更直接。
- 建议：优先试用，和现有 CAD skill、AgentCAD 做横向比较。

### 2. kernelCAD-web

- 仓库：[w1ne/kernelCAD-web](https://github.com/w1ne/kernelCAD-web)
- 状态：2026-06-01 仍有提交。
- 定位：agent-native CAD，强调源码优先、确定性验证、可导出制造文件。
- 判断：理念接近“AI 结构工程工作流”，但项目仍小，先观察。
- 建议：列入观察清单，暂不投入主线。

### 3. freecad-ai

- 仓库：[ghbalf/freecad-ai](https://github.com/ghbalf/freecad-ai)
- 状态：2026-05-30 发布 `v0.15.2-alpha`。
- 重点：布尔操作保留参数化历史；带 FreeCAD 内置 AI 工作台、工具调用、技能、文件附件、视觉路由。
- 判断：相比普通 FreeCAD MCP，它更像完整的 FreeCAD 内置 AI 助手，值得和 FreeCAD MCP 一起评估。
- 建议：后续试用，重点看是否能减少坐标/视图/手性错误，并保留参数化树。

### 4. text-to-cad

- 仓库：[earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad)
- 状态：2026-05-31 发布/合并 `0.2.0`。
- 关联：我们已实际测试 CAD skill，并反馈过 Windows snapshot / Chrome Headless Shell 相关问题。
- 判断：继续作为基础 skill 关注。
- 建议：安装/测试 0.2 版本，确认之前的 Windows 问题是否缓解。

### 5. FreeCAD MCP

- 仓库：[neka-nat/freecad-mcp](https://github.com/neka-nat/freecad-mcp)
- 状态：最近重要更新为 2026-05-29 增加 `reload_document` 工具。
- 判断：目前仍是 FreeCAD MCP 方向的大项目，生态关注度高。
- 建议：作为 FreeCAD 自动化主参考之一。

### 6. mcp-freecad

- 仓库：[seansackowitz/mcp-freecad](https://github.com/seansackowitz/mcp-freecad)
- 状态：2026-05-30 有提交。
- 定位：约 70 个细粒度 FreeCAD MCP 工具，强调低 token 成本、结构化文本返回、截图只在明确请求时返回。
- 判断：这个设计理念很值得学习，尤其适合我们“不要靠截图瞎猜”的经验总结。
- 建议：和 `neka-nat/freecad-mcp` 做工具粒度、返回结构、参数化能力比较。

### 7. ZWCAD-Mechanical-MCP

- 仓库：[john0909/ZWCAD-Mechanical-MCP](https://github.com/john0909/ZWCAD-Mechanical-MCP)
- 状态：2026-05-31 有提交。
- 定位：中望机械版 CAD MCP，偏 2D/工程图、图框、标题栏、明细表、标注、块、图层等。
- 判断：对 3D 建模主线帮助有限，但对供应商工程图、BOM、图框标题栏自动化可能有价值。
- 建议：列入“工程图自动化”观察线。

## 当前路线判断

Onshape 仍可作为云 CAD 协作和 API 后端之一，但已经不是当前核心路线。当前更有价值的主线是：

1. 用 CAD skill / AgentCAD / build123d-mcp 解决参数化生成、渲染、验证。
2. 用 FreeCAD MCP / freecad-ai 验证复杂参数化历史和可编辑性。
3. 用 GitHub 日志沉淀每次实战中的错误、修正、可复用规则。
4. 后续围绕 PC 机箱、散热器、液冷机柜，逐步形成可公开的硬件 CAD agent demo。

## 建议动作

1. 下一步优先试 `build123d-mcp`。
2. 随后试 `freecad-ai`，判断它是否比 FreeCAD MCP 更适合工业结构任务。
3. 继续跟进 `text-to-cad` 0.2 版本，确认 Windows snapshot 问题。
4. 暂时不把 Onshape 作为主战场，只保留为可选后端。
